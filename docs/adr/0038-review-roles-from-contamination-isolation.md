# ADR 0038: Review roles from contamination isolation, not a lens taxonomy

Date: 2026-07-24
Status: Accepted. Supersedes [ADR 0037](./0037-lens-set-organizing-principle.md) (the lens organizing principle), the lens-set decisions of [ADR 0023](./0023-multi-lens-generation-and-merge.md), and the whole of [ADR 0034](./0034-review-mode-and-lens-set-dials.md) (both dials and the subagent dispatch layer). [ADR 0035](./0035-intent-lens-reads-the-prs-own-claims.md)'s intent agent survives with its rationale sharpened, not weakened. Amended 2026-07-24 (#299): decision 6's dispatch shape is replaced by an orchestrator session spawning the roles as subagents; the role set, prompts, and every other decision stand.

## Context

The lens set has been tuned by measurement that cannot exist. Recall is unmeasurable at this PR volume (#185 closed for it), and the runs that did steer the set were single draws from a non-deterministic system: ADR 0037 re-added `data-flow` on an n=3 fixture run whose decisive catch was one bug (sounds-abroad#165) in one execution, while admitting in the same breath that "n=3 is not a recall distribution" and that the principle is "a judgment frame, not a measurement result." The set has oscillated accordingly: `correctness` shipped (ADR 0023), was deleted as redundant (#226), and returned renamed `data-flow` (#283). An axis this sensitive to single samples is not carrying signal; it is amplifying noise.

The taxonomy critiques already on file (#279 duplicated class definitions, #280 missing design axis, #281 tangled scope/input/domain axes) all point at the same root: the set was organized by *bug class* and *attention budget*, neither of which survives contact with the measurement problem. Comparing "general vs general+data-flow" or any pair of nearby lens strategies requires rate estimates that non-determinism plus a 1-3 PR sample cannot yield.

Meanwhile the structure worth keeping was already in the pipeline, unnamed: the generators never see the PR description (ADR 0035 gives it only to `intent`), and the editor re-reads everything on a fresh context (ADR 0016). Those two separations are not budget bets. They exist so one reading cannot contaminate another.

## Decision

The organizing question changes. Not "which lens set is optimal", which is unanswerable here, but "what is the minimal separation that contamination isolation forces". Everything else runs in one head.

1. **Only contamination isolation justifies a separate agent.** Three forces could motivate a split; two are rejected as grounds:
   - *Attention/budget* ("a second deep read catches what a broad read skims"): a bet whose payoff is unmeasurable in this operation. Rejected as a split criterion; depth guidance belongs inside a prompt, not in a second agent.
   - *Failure isolation and timeouts*: an engineering concern solved by process-level fan-out, indifferent to how many agents exist. Not a split criterion.
   - *Contamination isolation*: an agent that reads the author's claims will read the code as the claims say it works; a generator that grades its own findings will grade them kindly. These are structural, hold at any sample size, and are the one ground this ADR splits on.

2. **The pipeline is three roles: two generators and a verifier.**
   - **`code`**: reads the diff, the surrounding code, and the repo's documented conventions. Never sees the PR description, linked issues, or commit messages: all three are the author's claims, so it reports what the change actually does, anchored to nothing but the code. Its prompt enumerates the hunt list explicitly, Pocock-style. Hard classes: correctness, and the four data-flow classes (cross-component state, caller-contract, co-varying state, async/ordering) that previously justified a second agent; the checklist is the depth instruction (#279 dissolves: one source, one prompt). Judgment classes, each finding labelled as a judgment call rather than a defect:
     - maintainability, with performance and security posture folded in
     - tradeoff appropriateness: is what the change buys worth what it costs, judged against the repo's conventions with no author rationale in view
     - the Fowler smell baseline, restricted to smells visible in the diff itself
     - an unannounced mix of structural and behavioral change in one diff (Beck, *Tidy First?*)
     - a test that asserts a mechanism rather than an outcome, a class this repo has been bitten by (#252 asserted a neighbour's implementation and #253 broke `main` through it)
     - a behavior change carrying no test change, with room for the legitimately untestable
   - **`intent`**: reads the PR description, linked issues, and commit messages against the diff, and answers "does the change do what it says". Mechanically as ADR 0035 except one added input: commit messages, which ADR 0035's ladder excluded and the refactor-claim check below requires. Two extensions in kind: the *stated rationale* is checked, not just the stated behavior (a claim like "cached because the lookup is hot" is confronted with whether the cache is on that path), and a `refactor:`/`chore:`-prefixed commit claiming behavior preservation is hunted for the behavior delta it denies having. Its justification is now symmetric input isolation rather than "a different input": `code` is quarantined *from* the claims, `intent` exists to *confront* them.
   - **`editor`**: the existing ADR 0016 editorial pass, unchanged. Fresh context, everything as input, adversarial stance toward the generators' findings. Generation never self-grades.

3. **The domain lenses (`perf`, `security`, `tests`) are deleted.** They read the generators' own input with a narrowed prompt: attention bets, exactly the class decision 1 rejects. The eval corpus never held a defect they would catch (#249), and no measurement at this scale could show their marginal recall. A repo where one of these domains is load-bearing tunes the `code` prompt's checklist, which is a prompt edit, not an agent.

4. **`data-flow` is deleted as an agent and kept as checklist lines.** The one recorded catch (#165) is an existence proof that the classes matter, not that a second same-input read is how to find them. If the single-head checklist read misses a future cross-component bug that a split read would have caught, that is one more single draw, and re-splitting on it would repeat the oscillation this ADR exists to stop.

5. **Repo conventions are an input, not an agent.** The `code` role receives the repo's documented standards (CLAUDE.md, docs/) alongside the diff; Fowler-smell style judgment lives in its checklist as labelled heuristics, repo docs overriding. A conventions document is reference material, not a contamination source, so nothing forces a separate reader (#280 answered: in scope, as input).

6. **The subagent dispatch layer and both dials are deleted.** `REVIEW_MODE` dies with the slash-command-wrapper dispatch it selected (measured pure overhead, ADR 0034: equal recall, 27-39% more tokens). `REVIEW_LENSES` dies because the role set is fixed: two generators, one editor, `intent` skipping itself when the PR describes nothing (ADR 0035). The lens slash-command files retire with the mode.

   *Amended 2026-07-24 (#299), by explicit operator decision:* generation dispatch is one orchestrator `claude -p` session per review that spawns the roles as parallel subagents via the Agent tool (the shape the first version of this ADR rejected below); the editor stays its own sequential `claude -p` process. Measured after shipping (2026-07-25, #293): the two dispatch shapes are a dead tie on recall (N=10 per arm per fixture, 15/30 caught on both arms, noise 0 in all 60 runs, indistinguishable cost), so the shape stands on the structural argument alone (orchestration delegated to the claude program's harness rather than this repo's bash, whose process-coordination layer shipped the #192/#197/#251 class of bugs). The rejection's three costs are handled as engineering, not grounds:
   - *Slot accounting:* the orchestrator charges one slot per spawned role, acquired all-or-nothing (concurrent orchestrators each holding a partial claim would deadlock) and clamped to the pool size, so the pool keeps bounding concurrent API sessions honestly.
   - *Per-role sidecars:* each role subagent writes its own fenced payload to its named scratch file, so per-role raw files and the count-agnostic merge survive unchanged, and no payload round-trips through the orchestrator's generation. Per-role *cost* attribution is genuinely lost (stream-json exposes only the session aggregate); the generation stage emits one cost sidecar and the review total stays correct.
   - *Failure isolation:* the CLI has no per-subagent timeout, so `REVIEW_AGENT_TIMEOUT` bounds the whole orchestrator; the orchestrator tolerates a failed role without retrying or touching its file, and a payload written before a timeout still reaches the merge, which already rolls a total loss up to `all-lenses-failed` (ADR 0023).

7. **Merge, gate, and posting are untouched.** Two generators' findings union, dedup, confidence-gate, and post exactly as five lenses' did (the pipeline was lens-count-agnostic by design, ADR 0023). Per-axis reporting in the posted review is out of scope here and stays a candidate follow-up.

## Considered and rejected

- **One reviewer reading everything.** The simplest shape, and the null hypothesis this ADR starts from. Rejected on the one ground decision 1 accepts: it hands the author's claims to the only pair of eyes reading the code, and an agent told "this restores the playing context" reads the code looking for confirmation. The two-generator split is the minimal isolation, not an ensemble bet.
- **Keeping `data-flow` as a second deep read.** Its evidence is one catch in one run of a non-deterministic system, and its cost is every review. Decision 4.
- **A separate `standards`/`design` agent.** Pocock's skill separates Standards and Spec, but his axes differ by *input documents*, and a conventions file is not a contamination source. Folding it into `code` keeps the input-isolation criterion clean; splitting it would be an attention bet in disguise.
- **An orchestrator session spawning role subagents (one `claude -p`, parallel Agent calls).** ~~Buys in-context aggregation, but costs process-level failure isolation (one session, one timeout), breaks the slot pool's concurrency accounting (one slot, N hidden API calls), and loses per-role cost/raw sidecars. The aggregation it buys is the editor's seat anyway.~~ *Accepted by the 2026-07-24 amendment (#299).* This entry recorded a decision flagged as open being resolved inside the draft rather than asked; the operator overrode it to the orchestrator shape, and its costs are handled as engineering in amended decision 6. The next-phase motivation is structural: splitting generation into more roles (the planned checklist-split comparison in Consequences) fans out inside one session instead of multiplying OS processes.
- **Per-repo role sets.** With the set fixed at two generators whose scope is total, there is nothing left to vary per repo except prompt content, which forks already own via the bundle (ADR 0007).

## Consequences

- **Prompt rewrites, not renames.** `review-agent-code.md` and `review-agent-intent.md` are written fresh to this ADR's role definitions (the code prompt gains the enumerated checklist and the conventions input; the intent prompt loses nothing). `review-agent-general.md`, `review-agent-data-flow.md`, `review-agent-perf.md`, `review-agent-security.md`, `review-agent-tests.md` are deleted, and all six lens dispatch command files retire with the dispatch layer: five belonged to deleted agents, and the intent role's served a layer that no longer exists.
- **`review-pr.sh` sheds its lens machinery**: the `LENS_COMMANDS`/`LENS_LABELS` selection loop keeps only two fixed roles, the `REVIEW_MODE` fork and subagent branch go, `REVIEW_LENSES` parsing goes, `.env.example` drops both keys.
- **Tests and eval follow**: lens-taxonomy, review-mode, and dispatch tests rewrite against the two-role shape; eval fixtures re-run under the `code` prompt to re-baseline.
- **Issue ledger**: #279 closes (dissolved), #280 closes (answered by decision 5), #281 closes (the axes question is answered by replacing the taxonomy), #249's lineage ends. #88 records the redesign.
- **The editor's slash-command wrapper dies with the dial that selected it**: deleting `REVIEW_MODE` leaves the editor only its directly-prompted shape, which was already the shipped default. The judge-fix and reply wrappers still dispatch through slash commands (the shape ADR 0034 measured as overhead on the lens path) and are parked as their own issue, along with retiring the now-consumerless `edit-review.md`, rather than widened into this change.
- **What this gives up, and the planned test of it:** if attention dilution is real and large, a single `code` head will miss depth a split bought, and no single-draw comparison can detect the loss. The comparison is planned as a second phase, run the only way a non-deterministic reviewer can be compared: the consolidated `code` prompt versus a split-by-checklist-section variant, each run N times over fixed PRs with known defects (the eval fixtures), scored by how often each finds the known defects across runs. Frequencies from repeated runs are evidence; another single draw is not (decision 4).
